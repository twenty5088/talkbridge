日期：2026-11-07　前一版設計：`2026-11-07-talkbridge-design.md`（本文件只寫改變的部分，其餘照舊）

## 1. 為什麼要改

- 【Kevin 決定】現在的「自動輪流」寫死一人一句。Kevin 實際會連講兩三句中文；照現在的做法，第二句中文會被當成對方的英文去辨識，結果是錯的。
- 【Kevin 決定】要由 App 自動判斷：下一句如果跟前一句同一種語言，就表示同一個人還沒說完，要繼續翻、繼續播。例：太太說中文 → 翻成英文播出 → 太太再說一句中文 → 再翻成英文播出。
- 【Kevin 決定】先上網看其他即時翻譯軟體怎麼讓過程順暢（第 2 節）；另外要把各種使用情境想清楚、寫成測試，把找到的不方便處一起修掉（第 4 節）。

## 2. 其他翻譯軟體的做法（2026-11-07 網路調查）

| 軟體 | 怎麼做 | 我們可以學的 |
|---|---|---|
| Google 翻譯「對話」 | 在選好的兩種語言之間自動偵測說的是哪一種；靠停頓判斷換人；可開「自動播放」。關掉自動偵測就要每次按該語言的麥克風。 | 一個麥克風、兩種語言自動判斷；保留手動按鈕當備用。 |
| Apple 翻譯 App | 對話模式有「自動偵測」「自動翻譯」（自動偵測開始與停止說話）「播放翻譯」三個開關。 | 同上；自動偵測可以關。 |
| Microsoft Translator | 「自動模式」不用按按鈕；麥克風變綠色表示可以說話。 | **明確顯示「現在可以說話」**。 |
| Timekettle T1（翻譯機） | 沒有語言偵測，要事先設好兩邊語言、輪流講；評測建議不要搶話。 | 搶話、同時說話本來就難，不做。 |

技術面：Apple 的語音辨識每個辨識器只能辨識一種語言，沒有內建「判斷說的是哪種語言」的功能。網路上有人提過「同時開兩個辨識器聽同一段聲音、比較信心分數」，但沒有找到驗證過的例子，**一定要實機測**。

## 3. 新的「自動」模式

### 3.1 使用方式
- 【Claude 判斷】模式切換仍是「手動輪流｜自動」兩格；「自動」取代原本的「自動輪流 Beta」（固定交替不再保留）。
- 【Claude 判斷】自動模式下，底部改成一個大按鈕「開始對話」（對話中變成「暫停」），學 Google／Microsoft 的單一麥克風。「對方說話」「我說中文」兩個按鈕縮小留在下面，當成「強制指定下一句是誰說」的備用。
- 開始後：同時用中文和對方語言聽 → 停頓達設定秒數（預設 2 秒）→ 判斷是哪種語言 → 中文：翻成對方語言、倒數 2 秒播出；對方語言：翻成中文播出 → 播完 → 再同時用兩種語言聽。同一個人講幾句都可以。
- 畫面要清楚顯示麥克風狀態（學 Microsoft）：聆聽中顯示綠色「現在可以說話（中文或 English）」；翻譯／倒數／播放中顯示「請稍等，麥克風已關閉」。這段時間說的話不會被收到（第 4 節 P10）。
- 每張對話卡片標示判斷結果，例如小字「判斷：中文」。
- 停頓秒數：沿用 v37 已做好的設定（預設 2 秒、1.2–4 秒可調），手動與自動模式共用。【Kevin 決定】
- 【Claude 判斷】自動模式下按小按鈕「對方說話／我說中文」＝只指定**下一句**是誰說（只用那個語言的辨識器），這句結束後回到兩種語言一起聽。

### 3.2 怎麼判斷是哪種語言【Claude 判斷，需實機驗證】
- 同一段麥克風聲音同時送進兩個辨識器：中文（zh-TW）與對方語言。
- 說完後各自拿到文字與信心分數，算兩個分數，綜合比較：
  1. **文字像不像該語言**：中文辨識結果裡中文字的比例；對方語言辨識結果裡該語言文字的比例（英文／印尼文＝拉丁字母、泰文＝泰文字母、韓文＝韓文字母、日文＝假名＋漢字）。
  2. **辨識器自己的平均信心分數**（Apple 有提供時才用）。
- 兩邊差距夠大 → 確定。差距太小或兩邊都很短（例如「OK」「好」）→ **不確定**：照輪流順序猜（上一句是中文，就猜這句是對方說的），卡片標「判斷不確定」。
- 計分規則寫成純函式放在核心套件，用測試固定下來；門檻值集中在設定檔，實機測完再調。
- 日文和中文都有漢字，最容易判斷錯：日文以有沒有假名為主要依據。

### 3.3 判斷錯了怎麼辦
- 每張卡片有「換成另一種語言」按鈕。按下後改用另一個辨識器的文字、反方向重新翻譯並播放。兩份文字只放在記憶體、只保留最近一句，不存錄音，符合原本的隱私規則。

### 3.4 不能同時開兩個辨識器時
- 如果實機上第二個辨識器啟動失敗或中途出錯，自動降級為「固定一人一句」（原本的行為），畫面提示「這台手機無法同時判斷兩種語言，改為一人一句輪流」，對話不中斷。
- 對方語言只能用 Apple 伺服器辨識時（例如泰文、印尼文可能如此），照舊標示「需要網路」，判斷照樣進行。

### 3.5 Kevin 的兩個決定（2026-11-07）
- 【Kevin 決定】**先做實測版**：App 設定裡多一個「語言判斷測試（實驗）」畫面，兩個辨識器同時聽，顯示兩邊的文字、信心分數、是否在手機上辨識、錯誤訊息。Kevin 在太太手機上每種語言講幾句並截圖；確認兩個辨識器能同時跑、拿到真實分數後，才做完整功能，門檻依實測資料設定。實測版是拋棄式，完整功能開發時移除。
- 【Kevin 決定】泰文、印尼文若只能用 Apple 伺服器辨識，**照樣自動判斷**（太太的中文也會經過 Apple 伺服器），畫面標示「需要網路」。

## 4. 使用情境總檢查（找到的問題與修法）

我依照現在的程式逐一推演使用情境，找到下列問題。每一項都要先寫一個會失敗的測試，再修到通過。

| # | 情境 | 現在會怎樣 | 修法 |
|---|---|---|---|
| P1 | 太太連講兩句中文（Kevin 回報） | 第二句被當成英文辨識，翻錯 | 第 3 節自動判斷 |
| P2 | 對方連講兩句、或講超過 30 秒被切成兩段 | 第二段被當成中文 | 第 3 節自動判斷 |
| P3 | **對話中螢幕自動鎖定** | 手機閒置約 30 秒～1 分鐘就鎖螢幕 → App 進背景 → 對話被強制停止 | 對話進行中（非待機）不讓螢幕自動鎖定；回到待機後恢復 |
| P4 | 自動模式下聽到雜音、辨識出空白 | 畫面顯示「沒有聽到內容」，自動模式**靜靜停住**，但畫面還寫著輪到誰 | 自動模式忽略空白結果，繼續聽 |
| P5 | 自動模式下想重播某一句 | 因為一直在聆聽，卡片的「重播」按了沒反應 | 按重播＝暫停聆聽 → 播放 → 播完繼續聽 |
| P6 | 自動模式 15 秒沒人說話 | 自動暫停，要再按一次；對方看畫面、想一下就超過 15 秒 | 【Claude 判斷】自動模式改成 60 秒沒聲音才暫停；暫停後按「繼續對話」 |
| P7 | 翻譯失敗按「再試一次」 | 回到待機，要重講一次 | 「再試一次」改成用同一句文字重新翻譯 |
| P8 | 手機喇叭播出的外語殘響被麥克風收到 | 自動判斷後風險更高：自己的英文播放可能被當成對方說話，又翻回中文，形成迴圈 | 新聽到的文字如果跟剛剛播出的譯文幾乎一樣就丟掉；測試要涵蓋 |
| P9 | 對話卡片越來越多 | 新卡片在畫面下方，不會自動捲過去 | 有新卡片時自動捲到最新一張 |
| P10 | 倒數或播放時就開口說話 | 麥克風關著，這段話被漏掉，使用者不知道 | 第 3.1 節的「現在可以說話／請稍等」明確顯示 |
| P11 | 自動模式中換語言、按全部停止、來電、耳機斷線、切到背景 | 已會停止，但要確認自動模式（兩個辨識器）也都乾淨關掉、不殘留麥克風 | 補測試 |
| P12 | 手動模式按錯按鈕（對方說話卻按了「我說中文」） | 用錯的語言辨識，翻出亂碼 | 【Claude 判斷】手動模式也同時用兩種語言聽；判斷結果和按的按鈕不同、而且判斷是確定的時候，以判斷為準並提示「已自動改成對方說的話」。不確定時以按鈕為準 |

### 4.1 測試要涵蓋的情境（寫成自動測試）
- 五種對方語言 × 中文：各自判斷正確；連續兩句同語言；中英交錯三輪。
- 短句（「OK」「好」）判斷不確定 → 照輪流猜並標示；按「換成另一種語言」後改成反方向。
- 日文含假名判斷成日文；全漢字的短日文判斷不確定。
- 第二個辨識器失敗 → 降級一人一句並提示，對話繼續。
- 播放殘響（和剛播出的譯文一樣）被丟掉，不會形成迴圈。
- P3～P12 每一項至少一個測試；UI 測試涵蓋「開始對話／暫停」大按鈕、麥克風狀態文字、卡片判斷標示、自動捲動。
- 原本 119 個單元測試與 14 個 UI 測試全部保留並通過（行為改變的照新規格修改，並記錄原因）。

## 5. 不做的事
- 不用聲紋分辨是誰在說話（同語言的兩個人分不出來，這個情境本來就不存在）。
- 不處理兩人同時說話、搶話。
- 播放時不收音（避免把自己的播放辨識進去），這點不變。
- 不存任何錄音；判斷用的兩份文字只在記憶體保留最近一句。

## 6. 只能在實機確認的事（加進實機測試計畫）
- 兩個辨識器能否在 iPhone 上同時跑；耗電與發熱。
- 五種語言各自的判斷準確度，特別是日文；吵雜環境下的誤判。
- 喇叭殘響過濾在實際音量下是否足夠。
- 螢幕不鎖定是否生效。

## 7. 留給實作者決定的
- 兩個辨識器共用一個麥克風輸入的實作方式、信心分數的取得方式、門檻的初始值（先依測試資料設定，實機測完再調）。
- 「換成另一種語言」按鈕的圖示與位置；「現在可以說話」的顏色與文字大小（要符合原本的無障礙規則：文字＋圖示、Dynamic Type）。
